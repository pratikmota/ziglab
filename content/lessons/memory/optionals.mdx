`?i32` is either an `i32` or **null**. Null is missing, not zero. Zero is a real `i32`.

You do not read an optional as if it were always there. `orelse` gives a fallback when the value is null.

```zig
const std = @import("std");

pub fn main() void {
    const maybe: ?i32 = null;
    const n = maybe orelse 4;
    std.debug.print("{d}\n", .{n});
}
```

Here `maybe` is null, so `n` becomes `4`. If you bind `maybe` to `7`, `orelse` does not run and `n` is `7`. `maybe.?` unwraps and panics if the optional is null — prefer `orelse` or `if`.

`if (maybe) |value|` unwraps in a branch. `while` can do the same for a sequence of optionals. A pointer that might be missing is `?*T` — optional pointer — which you will treat with the same `orelse` / `if` tools.

`?` is **missing**. The next chapter’s `!` is **failed**. They look similar and they are not the same.
