A pointer is the **address** of a value with a known type. `*i32` means “pointer to an `i32`.” `&n` takes the address of `n`. `p.*` reads or writes the value at `p`.

```zig
const std = @import("std");

pub fn main() void {
    var n: i32 = 11;
    const p: *i32 = &n;
    p.* = 42;
    std.debug.print("{d}\n", .{n});
}
```

`p` is `const`, so you cannot point `p` at something else. You can still write `p.*` because `n` is `var`. `*const i32` would refuse the store.

**Stack versus heap.** Locals like `n` live for the function call (the stack). The heap is a region you ask for through an **allocator** you can see in the code. This path does not catalog allocator types. If you need the heap later, you will pass an allocator into the call that allocates — nothing here will do that for you in the background.

Do not return a pointer to a local. The local is gone when the function returns.
