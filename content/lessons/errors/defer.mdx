`defer` schedules a statement for the **end of the current block**. It runs when the block returns, including after an error return. Several `defer`s run in reverse order — last scheduled, first run.

```zig
const std = @import("std");

pub fn main() void {
    defer std.debug.print("done\n", .{});
    std.debug.print("work\n", .{});
}
```

This prints `work`, then `done`. The cleanup stays next to the setup instead of in a far-away `finally`.

`errdefer` is the sibling that runs **only if the block returns an error**. Use it to free something you allocated on a path that failed. It does nothing on the success return.

You will feel `errdefer` more once you allocate. For now: `defer` is “always on the way out”; `errdefer` is “only if we failed.”
